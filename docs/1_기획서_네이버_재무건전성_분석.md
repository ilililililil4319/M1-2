## Ⅰ. 추진배경 및 필요성

2024년 여름, 위메프·티몬(티메프)에 입점했던 수많은 온라인 셀러들은 판매대금을 제때 정산받지 못하는 사태를 겪었다. 플랫폼이 재무적으로 무너지고 있다는 신호는 사실 정산 지연이 뉴스로 터지기 전부터 재무제표 곳곳에 있었지만, 셀러 입장에서는 그 신호를 미리 확인할 방법도, 습관도 없었다.

온라인 셀러가 어떤 플랫폼에 입점할지 결정할 때 참고하는 정보는 대부분 "수수료가 얼마인가", "트래픽이 얼마나 되는가" 같은 영업적 조건에 그친다. 그 플랫폼을 운영하는 회사가 재무적으로 얼마나 건전한지, 즉 "이 회사가 앞으로도 안정적으로 정산금을 지급할 수 있는 회사인가"는 상대적으로 덜 살펴보게 된다.

금융감독원 전자공시시스템(DART)은 상장기업의 분기별 재무제표를 누구나 무료로 조회할 수 있도록 오픈API로 제공한다. 이 데이터를 시계열로 정리하면, 매출·이익 같은 성장성 지표뿐 아니라 부채비율·유동비율 같은 안정성 지표, 영업현금흐름 같은 현금창출력까지 추세로 확인할 수 있다.

이 프로젝트는 국내 대표 오픈마켓 플랫폼인 **네이버**를 대상으로 최근 수년간의 분기별 재무제표를 수집·분석하여, 온라인 셀러가 "이 플랫폼에 입점해도 괜찮은가"를 감이 아닌 데이터로 판단할 수 있도록 돕는 AI 비서를 만드는 것을 목표로 한다. 나아가 이 데이터를 이해하고 사용자의 질문에 맞춤 답변을 제공하는 대화형 웹 서비스로 구현한다.

## Ⅱ. 과제 목표 및 기대효과

**1) 과제 목표**
- [ ] 시계열 데이터의 트렌드/계절성(분기 패턴)/노이즈 개념을 설명할 수 있다.
- [ ] 결측치/이상치를 확인하고, 어떤 기준으로 처리했는지 설명할 수 있다.
- [ ] 이동평균, 증감률 등 시계열 기법을 왜/어떻게 적용했는지 설명할 수 있다.
- [ ] 데이터 요약을 시스템 프롬프트에 주입해 AI가 맥락에 맞는 답변을 하도록 구성할 수 있다.
- [ ] FastAPI + Firestore로 CRUD와 대화 기록 저장/불러오기를 구현할 수 있다.
- [ ] AI(Claude, 코디세이 API)를 활용하되, 최종 판단 근거는 스스로 설명할 수 있다.

**2) 기대효과**
① 플랫폼 선택을 "수수료·트래픽" 중심에서 "재무 건전성"까지 포함한 판단으로 넓힌다.
② 데이터 수집 → 정제 → 분석 → AI 서비스화까지 이어지는 엔드투엔드 경험을 축적한다.
③ 실제 사례(위메프 사태)와 데이터 분석을 연결해, 왜 이 지표를 봐야 하는지 스스로 설명하는 역량을 기른다.

## Ⅲ. 분석 개요 및 산출물 구성

**1) 분석 개요**

| 항목 | 내용 |
|---|---|
| 대상 기업 | 네이버(NAVER, 종목코드 035420) |
| 데이터 | 분기별 재무제표 9개 지표 (금융감독원 Open DART API) |
| 데이터 규모 | 최근 6년(24개 분기) × 9개 지표 = 최소 216개 이상 (long format) |
| 분석 질문 | ① 성장성·수익성·안정성 지표는 지난 6년간 어떤 추세를 보였는가 ② 안정성 지표(부채비율·유동비율)에 급격한 변화가 있었던 분기가 있으며, 어떤 이슈와 연결되는가 ③ 위메프 사태처럼 "정산 지연" 리스크를 미리 포착할 수 있는 재무적 신호(현금흐름 급감, 유동비율 하락 등)가 나타난 적이 있는가 |
| 시계열 기법 | 4분기 이동평균, 전년동기대비 증감률(YoY), 지표별 변동성(표준편차) — 3가지 적용 |

**2) 분석 지표 (9개)**

| 구분 | 지표 |
|---|---|
| 성장성 | 매출액, 매출증가율(YoY) |
| 수익성 | 영업이익, 영업이익률, 순이익률 |
| 재무안정성 | 부채비율, 유동비율, 자기자본비율 |
| 현금창출력 | 영업활동현금흐름 |

**3) 산출물 구성**

| 산출물 | 형식 |
|---|---|
| 웹 서비스 | FastAPI 백엔드(Render 배포) + 바닐라 프론트(Vercel 배포) — 데이터 기반 AI 채팅, 데이터 관리 CRUD, 대화 기록 저장/불러오기, 요약 정보 표시 |
| 분석 리포트 | REPORT.md — 주제/질문/데이터설명/시각화/인사이트/결론·한계 |
| 시각화 | 매출·영업이익 추이(+이동평균), 부채비율·유동비율 추이, 영업현금흐름 추이 (3개 이상) |
| 코드 | Jupyter Notebook (notebook/prepare_data.ipynb), backend/, frontend/ |
| 대시보드 고도화(보너스) | 시각화 그래프 1개 이상 + CSV/JSON 내보내기 + 다크모드 토글 |
| 문서 (docs/) | 기획서(PDF+md), 결과보고서(PDF+md) |
| README (루트) | README.md |

> 당신은 온라인 셀러가 네이버 스마트스토어 입점을 결정하기 전에 플랫폼(네이버)의 재무 건전성을 판단하도록 돕는 분석 비서입니다. 조건: 1) 제공된 재무 데이터에 근거한 사실만 서술하고, 입점을 권하거나 말리는 확정적 조언은 하지 않는다 2) 핵심 변동을 1~2문장으로 요약한다 3) 부채비율·유동비율 같은 전문 용어는 짧게 풀어서 설명한다.

## Ⅶ. 오류 처리 설계

| 발생 단계 | 예상 원인 | 처리 방식 |
|---|---|---|
| DART API 호출 실패 | 인증키 오류, 요청 한도 초과, 네트워크 문제 | 로컬에 미리 받아둔 CSV 백업본으로 대체, 오류 발생 시각·응답 코드를 로그에 기록 |
| 결측치 처리 시 | 특정 분기 공시 지연·누락 | 직전 분기값으로 보완하거나 결측 사실을 표로 명시, 처리 기준을 REPORT.md에 기록 |
| 코디세이 API 호출 실패 | 인증키 오류, rate limit 초과, 15초 이상 응답 지연 | AbortController로 타임아웃 처리, 최대 2회 재시도 후 실패 시 안내 문구 표시, 콘솔·로그 기록 |
| Firestore 연동 실패 | 서비스 계정 키 오류, 네트워크 문제 | 에러 메시지 콘솔 출력 후 재시도 안내, 로컬에서 키 유효성 우선 재확인 |
| CORS 에러 | 프론트(Vercel)·백엔드(Render) 도메인 불일치, `ALLOWED_ORIGINS` 미설정 | 배포 후 실제 프론트 도메인을 환경변수에 추가하고 재배포 |
| Render 콜드스타트 | 무료 티어 첫 요청 시 서버 슬립 상태 | 프론트에 "첫 응답은 최대 30초 정도 걸릴 수 있습니다" 안내 문구 표시 |
| 그래프 렌더링 실패 | data.json 형식 불일치, Chart.js 로드 실패 | 콘솔 에러로 원인 확인 후 데이터 타입 재검증, 실패 시 대체 문구 표시 |
| 배포 후 동작 이상 | 환경변수 미설정, Root Directory 설정 오류 | Render/Vercel 배포 로그 확인 후 로컬 재현·수정, 재배포 |
